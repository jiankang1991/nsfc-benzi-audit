# 2026-09-12 长稿与主张边界对照

四份短稿各做普通/skill 审核，一份约 1.6 万汉字长稿做普通/上一轮 skill/新版 skill 审核，共十一份报告。隐藏组别的独立核查确认：各条件都识别了材料中的实质问题，未发现无依据的强判断。**这组结果没有证明新版比普通审核或上一轮 skill 更准、更短。** 新增的确定能力是可选的源文件索引、来源变更拦截和中断续审记录；工具流程已实际检验。

## 执行条件

1. 两位独立材料作者分别生成四份主张边界节选和一份长稿，先交付原文与判据；不读仓库、skill、旧评测或修复讨论。材料、请求、原始判据及作者自查见 [extended](../../extended/README.md)，十个输入文件的字节冻结在 [input-manifest.json](input-manifest.json)。
2. 每份报告来自独立新上下文，各条件得到同一案例请求与相同原稿。普通组不能读 skill；其余组只增加指定冻结包。各组不读验收判据、其他报告或外部资料，不修改输入。使用宿主继承的同一模型，未另行指定或固定可复用的模型版本、随机种子。
3. 八次短稿运行使用新增长稿机制后的初版包；长稿另比较上一轮包和修复 TC-01 后的最终包。初版到最终版仅修改索引脚本对未闭合 `---` 的识别，主张判据、入口和其他资源不变。四份短稿均不以 `---` 开头，没有因纯工具修正重新运行并挑选结果。
4. 报告完成后，以 A/B 或 A/B/C 隐藏条件。两位独立核查者分别只读相应原稿、请求、判据和匿名报告。未提供条件映射或 skill。按实质问题、漏报、无依据强判断、有效额外发现、定位和最小修法核查，不按关键词评分，也不采用材料作者提出的可选 100 分加权方案。详见 [评分协议](assessment-protocol.md)。
5. 长稿评分包统一只提供主报告和证据附录；部分报告引用的工作文件实际存在，为避免透露工作方式没有交给评分者。已明确告知这一边界，不将材料包省略归责为作者缺件。必要计算均在报告/附录中可独立复核。评分者原始目录和结果完整保存在 [judging-packets.zip](judging-packets.zip)。
6. 主 agent 通读原文及全部主报告，复核独立评分，另对有限模型执行算术及分配枚举检查，记录在 [arithmetic-checks.json](arithmetic-checks.json)。这些是材料内的数学复算，不是实际实验或真实软件验证。

## 长稿：三个条件

共同原文含 15947 个汉字、18372 个字符、267 行，正文十章及附件五章。四个实质问题分别涉及到达信息遗漏、批次等权定义与读数等权程序冲突、固定正式窗口容量不足、启发式输出误标为最优真值。其中三组主要证据相隔超过全文汉字数的一半；已有合理安排另置于后文，不能只读摘要或各段孤立判断。

新版组实际使用了索引脚本，并保留 [阅读与未决记录](long/A/work-notes.md)；上一轮组也主动生成了工作笔记与算术记录。索引是否生成不作为语义覆盖得分，不能由报告中的“全文”字样反推实际逐字阅读。原始索引和复算文件在运行 ZIP 中。

新版附录更长，核查者指出其中重复了多处主报告建议；另有一句“初始化等额外延迟”略含混，标准初始化实际上已计入十二分钟，应理解为规程外开销。该措辞不改变容量结论，不计强误报。原报告保留原样，没有为了本批结果改写并重评；这批测试不能证明已有精简规则稳定降低了交付篇幅。

## 工具及修稿实测

独立工具评估实际完成两来源、十五块的建索引、读取、检查点、来源修订、拒绝旧定位、重建与续审，发现 TC-01：首行分隔线 `---` 没有元数据闭合符时，初版误把全文当作元数据，导航退化为超大单块。主 agent 用回归测试复现失败后修复；真正闭合元数据的对照结果不变。原始报告、调用及修正对照见 [tool-check.zip](tool-check.zip)。

最终脚本另通过 [可移植流程重放](../../../scripts/replay_review_workflow.py)；[workflow-replay.zip](workflow-replay.zip) 保存结果。重放检查点里的结论是预编写的测试文本，只验证工具操作及版本边界，不能算第二次模型语义审核。十九项单元测试（十二项索引、七项仓库验证器）实际通过。

独立修稿者只读新版报告、附录和原稿，实际产出 [修订稿](revision/application-revised.md) 和 [落实说明](revision/change-notes.md)。主 agent 复核 [全部差异](revision/changes.patch)：四项意见均有具体落点；错误基准和汇总对象得到文本更正，到达接口和设备窗口保留具体待确认方案。没有覆盖历史输出、冒称程序已重跑或编造设备许可。完整输入/输出在 [revision-exercise.zip](revision-exercise.zip)，范围及逐项状态见 [修稿复核](revision/verification.md)。这只检查新版报告一次实际修稿，不是三个条件的修稿效果对照或真实用户体验测量。

## 证据限制

这是同一模型体系、每条件单次的合成材料检查。长稿比上一轮节选长，但仍只有一份纯文本，不能代表真实三十页 PDF、图表提取、真实未公开研究或跨模型稳定性。规则已有反例提示的材料更适合检验边界，不能据此推断真实申请的漏报率。外部文献、年度政策、设备许可、实验正确性和资助成功率均未在本轮核验。没有将评测数量、总分或零误报记录包装成普遍性能承诺。
