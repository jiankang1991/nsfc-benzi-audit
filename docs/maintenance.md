## 验证方式

行为用例在 [evals](../evals/README.md)。向独立评估者只提供请求、skill 快照与原始测试材料；保留预期判据给验收者，避免泄露标准答案。用正反例检验判断，不用关键词匹配冒充行为测试。记录实际输出及失败后修正；语法、发现和资源验证另记。

新增规则应有适用范围和误报反例。若修改只涉及表达、链接或样式，使用相应检查即可，不要求扩展整套评测。首轮结果记录在 [修复与验证记录](validation-2026-09-12.md)，后续结果记录在 [机制改造记录](mechanism-2026-09-12.md) 和 [长稿与续审改进](long-review-2026-09-12.md)。

## 机制规则的唯一维护位置

| 规则 / 内容 | 维护位置 | 来源性质与替代关系 |
| --- | --- | --- |
| COV：问题、任务、成果及跨章覆盖 | [核心判断](../nsfc-benzi-audit/references/benzi-logic.md) | 文本承诺与支撑关系的逻辑判据；替代数量相等、固定串行组织等代理判断 |
| EVD：证据层级、能力与资源 | 同上 | 推断所需证据；替代 SCI、本人预发现、逐任务新增支出等统一门槛 |
| PRED / CAUSAL | [研究主张](../nsfc-benzi-audit/references/research-claims.md) | 预测有效性与因果主张的不同证据负担；替代统计研究一律补机制的要求 |
| MODEL / INVERSE / MEASURE | 同上 | 对实际模型、反演或测量界主张的条件判断；替代所有模型都需 PDE 条件、所有反演都需固定证明清单等要求 |
| TRANSFER / NOVEL | 同上 | 验证范围与外推、对比证据与新颖性主张相匹配；替代固定验证层级、项目命中数直接否定创新 |
| 必改前反查、优先级、编号与去重 | 核心判断；[入口](../nsfc-benzi-audit/SKILL.md) 和 [报告模板](../nsfc-benzi-audit/assets/report-template.md) 调用 | 审核工作方法；重要程度与证据确定程度分开，支持撤销和无必改结论 |
| 标题、摘要、段落组织及读者导航 | [表达建议](../nsfc-benzi-audit/references/writing-advice.md) | 可选写法；替代措辞、固定句式或章节位置直接形成必改项 |
| 年度、类别、阶段与正式申报要求 | [官方规则](../nsfc-benzi-audit/references/current-rules.md) | 带日期的外部来源；本次机制改造未重新在线核验，不增加官方规则有效期 |
| 学科证据与材料专项 | 对应学科、代表作、检索及审核面参考 | 只细化实际适用条件，不另建更强的通用门槛 |
| 长稿定位、跨文件证据与中断续审 | [长稿工作流](../nsfc-benzi-audit/references/long-draft-review.md)、包内 `scripts/review_index.py` | 可选的本地工具与工作记录；散列和分块不等于原稿版本正确或语义审核完成 |

各主张卡的适用条件、检查对象、实质失败、反例和依据集中写在卡内。它们是诊断判据，不是基金委正式条款。第一次自然材料对照主要覆盖 COV、EVD、PRED、TRANSFER 和复审；后续 [扩展材料](../evals/extended/README.md) 检查了 MODEL、INVERSE、MEASURE、NOVEL 的部分边界及长稿跨章证据。每种仅有少量合成材料，不代表整张卡、各学科或各模型均已验证，也没有证明使用 skill 优于普通审核。

## 规则准入、修订与退役

样本观察先作为观察保留，再判断是否足以形成候选规则。可能产生必改意见的候选须记录：编号与唯一位置、实际主张与适用条件、来源类型和定位、反例、违背后的后果、最小改法、验证材料和被替代的旧规则。具体格式见 [样本学习机制](../nsfc-benzi-audit/references/exemplar-learning.md#improving-this-skill-from-examples)。依据不足时仍作为待核实问题或写法观察，不升级为硬要求。

改规则时同时检索入口、参考、模板和示例中的同类表述与例外，直接修正冲突源和调用处。旧规则因依据失效或范围变化而退役时说明原因；不要在尾部不断追加“但也可以”的覆盖条款。反复出现在获资助样本里的写法，仍不能证明其缺失会导致不获资助。

行为测试先冻结材料和独立判据，再分别提供相同请求给使用与不使用 skill 的新上下文。评分者只看原文、判据和隐藏组别的产物，按证据判断漏报、无依据的强制意见、复审状态和修改可执行性；合理的额外发现允许纳入，不能把判据当作唯一答案。原始运行失败也保留，不用重跑后的好结果覆盖历史。

结构检查与行为评分分别执行：

```bash
python3 scripts/validate_repo.py
python3 -B -m unittest discover -s scripts -p 'test_*.py' -v
```

快照检查需显式选择对应版本的清单：`python3 scripts/validate_repo.py --manifest <清单路径>`。历史清单不应要求当前源码永远保持原字节；先在对应版本的独立副本中检查。脚本不验证外网链接、官方规则时效、公式正确性或真实申报质量。
