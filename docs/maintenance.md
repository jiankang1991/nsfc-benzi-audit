## 验证方式

行为用例在 [evals](../evals/README.md)。向独立评估者只提供请求、skill 快照与原始测试材料；判据留给评分者。用正反例检验：既要检出写作问题，也要不把样本偏好误报为必改。不用关键词匹配冒充行为测试。

新增或加强规则时，至少准备一个应检出的材料和一个表面相似但不应判必改的材料。只改表达、链接或样式时，运行结构检查即可。

## 规则准入、修订与退役

样本观察先作为观察保留，再判断是否足以形成候选规则。可能产生必改意见的规则须写明适用的实际主张、一个不应被判必改的反例和最小改法（格式见 [样本学习机制](../nsfc-benzi-audit/references/exemplar-learning.md#improving-this-skill-from-examples)）。规则过强时收窄触发条件或降级，不删除背后的样本观察；反复出现在获资助样本里的写法，不能证明其缺失必然导致不获资助。删除或降级一条信号前先实跑：用能触发它的同一批材料（craft、real 或新埋雷稿），在有该行、无该行两种条件下各跑一遍，比较它是否改变过任何条目的检出或分级；记录进 `evals/runs/`。只有「从未改变结果」的实跑记录才支持删除，理由写进提交说明。`19917ae` 未经这一步就精简了写作经验规则，随后在 `c279fbe` 回退（见上文 2026-09-14 一节）。这一做法借自 microsoft/ResearchStudio：它按审计周期计数，确认检查从未改变判定后才退役。

改规则时同时检索入口、参考、模板和示例中的同类表述，直接修正冲突源。结构检查与行为评分分别执行：

```bash
python3 scripts/validate_repo.py
python3 -B -m unittest discover -s scripts -p 'test_*.py' -v
```

脚本不验证外网链接、官方规则时效、公式正确性或诊断质量。
