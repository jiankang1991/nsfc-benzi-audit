# 2026-09-12 诊断机制改造

基于首轮修复提交 `6a0c627` 继续改造。原来的通用规则混有研究类型要求和写法偏好，个别参考仍把机制研究、串行任务、固定验证层级当作默认要求；默认模板也让同一问题在多个章节反复展开。本轮将这些要求按职责拆开，并实际比较使用与不使用 skill 的诊断表现。

本页保留第一次机制改造的结果和计数；所测 16 文件版本已作为 ZIP 快照保存在对应运行记录中。后续长稿工作流与新主张材料的验证见 [长稿与续审改进](long-review-2026-09-12.md)，不将本页的验证范围扩展到后来新增的脚本。

## 改了什么

| 原问题 | 当前机制 | 主要位置 |
| --- | --- | --- |
| 相似关键词触发不适用的要求 | 按实际主张选择判据，每张卡带适用范围、失败条件、例外和依据 | [研究主张卡](../nsfc-benzi-audit/references/research-claims.md) |
| 高影响担忧被直接写成确定缺陷 | 必改前检查适用性、全文反证、材料边界和最小修法；把重要程度与确定程度分开 | [核心判断](../nsfc-benzi-audit/references/benzi-logic.md) |
| 通用逻辑与措辞偏好混写 | 核心只维护覆盖、证据和意见判断；表达建议按需读取，不能形成科学硬门槛 | [表达建议](../nsfc-benzi-audit/references/writing-advice.md) |
| 入口默认加载过多参考 | 先读共享核心，再按任务、实际材料和所作主张读取有关部分 | [入口](../nsfc-benzi-audit/SKILL.md) |
| 一个问题在多章重复算作发现 | 一项根因一个稳定编号、一次完整说明；完整审核用简明覆盖记录，详细矩阵按需附录 | [报告模板](../nsfc-benzi-audit/assets/report-template.md) |
| 复审只看是否按旧意见修改 | 同时复核旧意见的依据，保持编号，允许撤销；文字改正与执行核实分开 | 核心、入口和报告模板 |
| 从样本不断累加通用规则 | 观察、候选、准入和退役分开；高影响规则记录反例、来源、替代关系与实际验证 | [样本学习](../nsfc-benzi-audit/references/exemplar-learning.md)、[维护说明](maintenance.md) |
| 原有测试提示答案较明显 | 独立生成自然写法材料，同请求分别审核，再隐藏条件评分 | [自然材料对照记录](../evals/runs/2026-09-12-mechanism/README.md) |

主张卡包括 PRED、CAUSAL、MODEL、INVERSE、MEASURE、TRANSFER、NOVEL。通用覆盖 COV 和证据 EVD 仍在核心维护，没有把所有判据另做成新的必填表。

信息通信、遥感、医学、科学问题凝练、代表作和 kd 参考同步收窄冲突口径：不要求所有统计研究补机制、不按条数或章节位置判脱节、不强制所有研究完成同样的验证阶段、不从作者关系或项目命中数推断能力与创新。README 的输出说明和相关示例也已同步；政策与医学外部来源沿用首轮注明日期的基线，未冒充本轮重新在线核验。

## 加载和报告结构

| 文件 | 改前行数 / 字符数 | 改后行数 / 字符数 |
| --- | ---: | ---: |
| SKILL.md | 58 / 8405 | 57 / 7363 |
| benzi-logic.md | 431 / 33780 | 76 / 9228 |
| report-template.md | 292 / 4674 | 60 / 1620 |

入口加核心从 42185 字符降至 16591，约减少 61%；相关研究主张和专项仍需按任务读取。这里量的是源码字符量，没有测得实际 token、响应时间或全任务成本，不能据此宣称运行加速 61%。

完整审核仍覆盖用户提供的全稿；短报告不等于少检查。默认只展开实质发现、必要对应关系、复审证据和真实核查限制，零发现也可直接交付。没有强制每次追加一个审稿 agent，也没有固定发现数量、置信概率或资助评分。

## 实际验证结论

三组自然材料、六次独立对照执行，使用与不使用 skill 都识别了全部三项预设实质问题，并正确放过没有实质矛盾的方案；独立隐藏组别评分和主 agent 原文复核均未发现无依据的强制整改。第三组五条旧意见的状态判断两组均成立。两份医学、检索回归报告也满足原有边界判据。

**不能据本次结果宣称 skill 提升了准确率。** 普通审核已经完成这些任务；没有加入旧版 skill 条件，也没有跨模型重复。报告总字符数由普通组 7860 到 skill 组 7765，仅差约 1.2%，且 skill 复审报告更长，不能声称整体篇幅稳定下降。此次确定完成的是规则简化、条件化、反查与复审机制，以及可复核的比较过程。

所有原始材料、六份逐字保留的回答、两份回归产物、独立判据及其歧义说明、评分和冻结清单见 [完整运行记录](../evals/runs/2026-09-12-mechanism/README.md)。材料在运行前生成，六份输出未被用于改写被测版本；评分后没有为这批样本调提示词并挑选重跑。

结构验证由 [validate_repo.py](../scripts/validate_repo.py) 检查本地资源、Markdown 链接/标题/围栏、JSON/SVG、入口与 LICENSE，显式选择清单时校验 SHA-256。[七项脚本测试](../scripts/test_validate_repo.py) 实际检查正确输入以及坏链接、坏标题、未闭合围栏、坏 JSON、授权不一致和快照变更/缺失。它们不替代诊断的语义评分。

本轮实际执行结果：七项脚本测试全部通过；仓库检查覆盖 73 个文件、51 份 Markdown、182 个本地链接、9 份 JSON 和 1 份 SVG，无错误；16 项 skill、9 项输入、11 项输出的冻结散列分别校验通过。`skill-creator/scripts/quick_validate.py` 通过，缓存的 Skills CLI 1.5.18 在 `--list` 模式下发现唯一 skill，未执行安装。`git diff --check` 及新增文本文件的尾随空白检查均通过。

## 尚未被这轮证据覆盖

三份当前稿约两千汉字，不能代表三十页的完整申请书。真实用户是否觉得报告更易修改、长文能否保持证据定位、各研究主张卡是否都能在不同学科和模型下稳定使用，仍需独立材料验证。下一次有合适材料时应预先固定这些问题和判据，不重复用已经读过的三组用例证明新改动泛化。

结构检查只证明所列格式和版本条件满足，不能证明科学正确性、当前政策有效性或资助成功。
