# 2026-09-12 长稿与中断续审改进

上一轮将规则按主张拆开，但仅用约两千字节选检验了部分判据。本轮增加长稿定位工具、可复现的中断续审检查，并用独立生成的长稿和其余主张材料继续验证。此前的诊断结论和测试记录保留，没有把新版本结果写回旧运行。

## 已落地的工作流

[长稿参考](../nsfc-benzi-audit/references/long-draft-review.md) 按需说明源文件地图、分段阅读、远距离反证、中断检查点和短报告交付。入口只增加一条路由；普通短稿无需额外读取这份参考或执行脚本。

[review_index.py](../nsfc-benzi-audit/scripts/review_index.py) 使用 Python 标准库，为用户选定的 UTF-8 Markdown/文本生成散列、章节和连续行块。它提供 `build`、`read`、`verify` 三个命令：

- 每个原始行都能定位，不重叠、不跳过；表格和代码围栏不在内部切开，超大块明确标记。
- 索引按相对路径保存，可与原稿一起移动；同名文件仍保留独立来源编号。
- 取段前核对全部来源的字节散列。文件修改后先停止旧定位，重新建索引并复核受影响证据。
- 索引不覆盖原稿或已有索引；编号只属于该快照，不能当作跨版本的意见编号。

实际读过的范围、未读范围、未决意见及其反证由审核者记录。索引生成成功、哈希未变或读取了一段文本，都不能自动证明语义审核完成。源文件散列也不能决定哪个版本才是用户指定的原稿。没有 Python 时可以用普通来源笔记继续审核。

主报告的长度与阅读范围分开控制：同一问题只讲一次，给出明确定位和最小修法；详细证据需要时另附。存在不同修复分支时说明各自影响，不替申请人悄然更换研究目标。

同时修正了代表作参考指向已删除旧段落的文字，改为调用核心 EVD 的“已完成部分与拟新增成果”判断。各研究主张卡本身未因这批材料新增特例。

## 独立工具实测及修正

独立评估者用自造的正文和附件实际走完建索引、读取全部十五个块、跨文件核对、保存检查点、修订两个来源、拒绝旧索引、重建与继续复审的流程。旧意见能保持编号，并区分文字已解决和外部事实尚未核验。

实测发现 TC-01：首行只有 `---` 分隔线且没有元数据闭合符时，初版脚本把全文误认为元数据，丢失标题地图，形成一个 oversized 块。原文未丢失，但导航失效。修复仅增加元数据闭合符的确认；回归测试先在初版失败，修后通过，真正闭合元数据的对照索引保持一致。

目前共有十九项单元测试：十二项索引测试和七项仓库结构检查测试，均已实际通过。[流程重放脚本](../scripts/replay_review_workflow.py) 另在最终 helper 上完整运行成功。它生成的检查点结论是预先编写的测试文本，只验证工具机制，不算另一次模型语义审核。原始独立报告与调用记录保存在运行记录的 `tool-check.zip`，最终重放记录在 `workflow-replay.zip`。

## 行为测试和版本

新增四份主张边界节选和一份 15947 汉字长稿。短稿按普通审核/使用 skill 两种条件共运行八次；长稿按普通审核、上一轮 skill、新版 skill 三种条件运行。每次独立上下文，只提供相同请求和该组原稿，评分者隐藏条件标签。

短稿使用工具修复前冻结的初版包；长稿使用上一轮包和修复后的最终包。初版到最终版仅有 TC-01 的脚本修正，四份短稿均不以 `---` 开头，主张判据和入口相同。短稿不因纯索引修正重复运行，工具影响由失败复现、回归和最终流程重放覆盖。

独立核查完成后，短稿两种条件都识别了两项实质问题，正确放过两份无实质矛盾的稿件，没有漏掉预设问题或产生无依据的强判断。四份主报告合计普通组 1416 汉字、skill 组 1802 汉字，skill 组约长 27%。

长稿三种条件均找到四项实质问题，没有强误报，均提供跨章定位和可执行修法；普通、上一轮、新版的主报告分别为 1034、1114、1062 汉字，均满足请求的约 1800 汉字限制。新版实际使用索引并保存阅读记录，但上一轮也主动维护了笔记。新版主报告加附录合计 3979 汉字，高于普通组 3455 和上一轮 2994；独立核查指出新版附录有重复建议及一处不影响计算的含混措辞，原始产物未改写。

因此，这批结果没有证明诊断准确率或报告篇幅改善。已验证的新增部分是来源定位、修改后拒绝旧索引、恢复工作所需记录和工具兼容边界。简明主报告的要求三组都满足，不能把这一点单独归功于新机制。

## 报告能否落到原文

独立修稿者只得到新版长稿报告、附录和原稿，没有 skill、答案判据或其他组报告，实际生成了另存修订稿。主 agent 通读差异及落实说明，四项意见均形成了具体文本改动：错误最优标签和汇总对象得到更正；估计器接口与设备窗口给出保持原目标的待确认拟案。原始输出、有效读数和历史表格保留，没有编造新实验、运行结果或设备许可。

接口设计选择、实际设备时段以及未提供的程序改版仍未落实，不能据此写成所有实施问题已经消除。产物和逐项复核见 [修稿测试](../evals/runs/2026-09-12-extended/revision/verification.md)。这验证了一次报告到文本修改的可执行性，没有测量真实申请人的使用体验，也没有做三组修稿效果比较。

实际产物、评分和适用限制见 [完整运行记录](../evals/runs/2026-09-12-extended/README.md)。每一版均保留可解压的完整 skill 快照与 SHA-256 清单，材料和产物另有清单；旧版本可以在独立目录恢复，日常源码可以继续维护。本轮没有新增官方规则或重新在线核验政策。

## 仓库验收

最终结构检查覆盖 136 个文件、85 份 Markdown、268 个本地链接、22 份 JSON 和 1 份 SVG，无错误；当前 18 项包清单、10 项输入和 39 项输出散列均通过。三个包快照分别恢复到独立目录后，16/18/18 项文件与各自历史清单相符；八个 ZIP 的完整性检查通过，十一组运行的 42 个原始文件与临时运行产物逐字节一致，十四份公开报告/附录的散列和篇幅记录一致。

官方 skill 格式检查通过；本地缓存 Skills CLI 在 `--list` 模式下发现唯一 skill，未执行安装。`git diff --check` 和八十个新增文本文件的尾随空白检查通过。十九项单元测试及最终工具流程重放的通过记录见上文；这些检查不替代行为评分或真实申请核验。

提交前的暂存检查另发现归档补丁的空白上下文前缀被 Git 当作行尾空白；已通过 `.gitattributes` 为 `.patch` 关闭 `blank-at-eol`、`blank-at-eof` 检查，保留补丁语法及冻结字节。其他文件仍使用正常空白检查。
